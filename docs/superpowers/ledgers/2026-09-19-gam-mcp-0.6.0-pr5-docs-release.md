**FINDING 1 — Task 5's test snippet contained a placeholder.** `{ /* … full args, no zod defaults … */ }`.
My own placeholder scan missed it because the pattern did not match this shape. Since `handler()` does no
zod parsing, an omitted `top_n` is `undefined` and slices to nothing — the test would have failed for an
unrelated reason and sent the implementer hunting. **Ruling: fixed in the plan before dispatch** (commit
`0ab5ead`) with real arguments read from the tool's schema. Cost if wrong: none; it is now concrete.

**FINDING 2 — Task 3's verification grep was wrong.** `grep -c "name: '" src/tools/*.ts` yields **41**, not
29/33, because tool files carry other `name:` keys. **Ruling: fixed in the plan before dispatch** — it now
points at `SHARED_TOOLS`/`SAVED_QUERY_TOOLS` and the on-the-wire assertion in `transports-e2e.test.ts`.
Cost if wrong: an implementer would have "verified" a number against a grep that cannot produce it.

**Ruling — README section ownership.** Tasks 1, 2 and 3 all edit `README.md`. Boundary: **T1 owns the
configuration table rows and line 5; T2 owns prose beneath the table and §Reliability; T3 owns §Tools,
§Resources, §Troubleshooting and §Example queries.** Each dispatch states its boundary and says the other
sections belong to a sibling task. Cost if wrong: a later task reverts an earlier one's edit — visible in
the review diff, cheap to fix.

**Ruling — documentation tasks verify by citation, not by test.** Tasks 1, 2, 3, 7 and 8 add no code and
therefore no test. Their verification is that every factual claim cites a file and line the implementer
read, plus the mechanical checks in the plan's final checklist. A reviewer applying a code rubric may flag
"no tests" — that is expected and not a defect for these five. Tasks 4, 5 and 6 are code and carry real
tests and mutations. Cost if wrong: a documentation error ships; the final whole-branch review is the net.

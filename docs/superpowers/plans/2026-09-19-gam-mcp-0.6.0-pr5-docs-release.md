## Global Constraints

- **Generic-MCP (CLAUDE.md).** Never bake publisher-specific data into code, fixtures or prose. This binds the README hardest: no network codes, no real advertiser, currency or time-zone values that imply a particular publisher. The repository was scrubbed of exactly this data; do not reintroduce it. Use `1234` and invented names in any example.
- **Documentation must be verified against the code, not against the previous documentation.** Every factual claim added to the README or spec cites a file and line the implementer has read. If a claim cannot be verified, it does not go in.
- **No AI attribution** in any commit message or PR body. Before every commit: `git log release/0.6.0..HEAD --format='%B' | grep -i -E '^(co-authored-by|.*generated with \[?claude|claude-session)'` must print nothing.
- **Never type a `\u` escape into an Edit/Write tool argument.** Tool arguments are JSON, so it decodes into a raw control byte in the file. Use a `python3` script with `chr()`. Scan changed files for control bytes other than tab before every commit; the scan must print nothing.
- **Absence is not permission.** The recurring defect class in this codebase.
- **stdout is the MCP protocol channel.** Logs go to stderr. Never `console.log`.
- **Tests are not typechecked** (`tsconfig.json` includes `src/**/*` only), so assert shapes explicitly.
- **Node >= 22.** `npm test` is `vitest run`; `npm run typecheck` is `tsc --noEmit`.
- **Conventional Commits.** PR 5 adds no breaking changes of its own except where a task says otherwise; do not invent `BREAKING CHANGE:` footers. Seventeen already exist across the release — **check any footer you write against its own diff**, because six on PR 4 needed correction.

- [ ] **Step 3: Change the signature to take the definition**

```ts
// The warning for a result whose report zone this server cannot name. The
// reason has to name what is actually unusable: PROVIDED is a source this
// server understands -- it is the zone name beside it that it cannot use --
// while any other source is one no zone follows from.
export function unknownZoneWarning(
  dateZone: string,
  definition: { timeZoneSource?: string; timeZone?: string },
): string {
  let reason: string;
  if (definition.timeZoneSource === 'PROVIDED') {
    reason = definition.timeZone
      ? `the report gives its time zone as ${JSON.stringify(definition.timeZone)}, which is not an IANA time zone name this runtime knows`
      : 'the report says its time zone was provided but does not say which';
  } else if (definition.timeZoneSource) {
    reason = `no zone follows from its time zone source, ${definition.timeZoneSource}`;
  } else {
    reason = 'the report states no time zone source';
  }
  return `GAM counted this report's days in a time zone this server cannot name: ${reason}. ` +
    `Those days may not cover the same hours as dates chosen in ${dateZone} (GAM_TIMEZONE).`;
}
```

### Task 7: the spec says what the code does

**Scope source:** §2. **Files:** `docs/superpowers/specs/2026-09-17-gam-mcp-0.6.0-design.md` (§1.1, §2.6, §6, §9).

- [ ] **Step 1: §6 gains the offset-time-zone refusal**

§6's list runs from line 334. Item 8 says `GAM_TIMEZONE` defaults to the network's zone instead of UTC — which does not cover an offset, because an offset is not an *unknown* zone. Verified breaking: 0.5.2 read the variable raw and handed it to `Intl`, which accepts `+08:00`; 0.6.0's `canonicalTimeZone` returns `null` for anything `Intl` resolves to a leading `+`/`-`, and startup stops. Append:

> 10. `GAM_TIMEZONE` must be an IANA zone name. A raw UTC offset (`+08:00`, `-0500`) was accepted by 0.5.2 because Node's `Intl` accepts one; it now stops startup. `Etc/GMT-8` and the like stay accepted — they are IANA names.

- [ ] **Step 2: §2.6's `pending` bullet states the weaker guarantee**

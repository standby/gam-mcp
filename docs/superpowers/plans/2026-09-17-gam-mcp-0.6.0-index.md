# gam-mcp 0.6.0 — Plan Index

> **For agentic workers:** each PR has its own plan file. Execute one PR's plan with superpowers:subagent-driven-development. PRs are **stacked**: each PR's branch starts from the previous PR's branch, and its plan is written against that branch's finished code. Do not start a PR whose plan file does not exist yet.

**Spec:** `docs/superpowers/specs/2026-09-17-gam-mcp-0.6.0-design.md`

**Why one plan per PR:** each PR builds on code the previous one produced. A plan written up front for PR 4 would describe files as they will not look after PRs 1–3. Stacking lets the next plan and PR start before the previous PR is merged; merge them in order (PR 1 into `main` first, then retarget each next PR to `main`).

## Global Constraints (apply to every PR)

- Node ≥ 22 (`engines`), TypeScript strict, ESM (`"module": "nodenext"`); imports use `.js` suffixes.
- MCP SDK stays `@modelcontextprotocol/sdk` v1 (spec D-5). No new runtime dependencies.
- Logs go to stderr only in stdio mode; never log credential values, only the source type (`file`, `json`, `adc`).
- Conventional Commits (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `chore:`); breaking changes carry a `BREAKING CHANGE:` footer. **No `Co-Authored-By` or any AI attribution** (repo `CLAUDE.md`).
- Commands: `npm test` (vitest), `npm run typecheck` (covers `src/` only — tests are not typechecked, so tests must be run, not just compiled), `npm run build`, `npm run verify:pack`.
- Generic-MCP rule (repo `CLAUDE.md`): no publisher-specific values in code, descriptions or fixtures. Tests use network code `1234` and invented names.
- Release: release-please opens a release PR after each merge to `main`. **Do not merge the release PR until all five PRs are merged and the live smoke test (spec §7.3) has passed.**
